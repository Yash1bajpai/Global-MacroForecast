# 🚧 Known Issues & Technical Debt

This document tracks current limitations, known bugs, and the roadmap for future enhancements. It demonstrates our commitment to transparency and continuous improvement.

## 🔴 Known Limitations

### 1. Publication Lag on OECD QNA Countries (Japan, India)
- **Description:** Japan and India GDP come from OECD Quarterly National Accounts (mirrored on FRED), which publish with a ~1-2 quarter lag. US GDP (FRED `GDPC1`) is typically one quarter fresher, so the four dashboards can have slightly different "last actual" quarters.
- **Impact:** Cosmetic only — the 8-quarter forecast window always starts immediately after each country's latest actual observation.

### 2. Directional Accuracy Near Coin-Flip for Japan & Germany
- **Description:** Since removing the `gdp_growth_yoy` target leakage (v1.5.0), honest directional accuracy is ~58% (Japan) and ~52% (Germany). Both countries publish QoQ growth rates that hover around zero, so the sign of the next quarter is inherently hard to predict.
- **Impact:** RMSE for both is unaffected (~1.65 / ~2.37). Consider annualizing targets or using a sign-aware loss if directional skill matters more than magnitude.

### 3. India Unemployment Series Discontinued
- **Description:** FRED discontinued `LRUNTTTTINQ156S` (India harmonized unemployment), so `data/raw/india/unrate.csv` no longer refreshes. India's model never used it (its feature table never included unemployment), so there is no model impact — the stale raw file is retained for provenance only.

## ✅ Resolved

### India SARIMA Model Omission ~~(RESOLVED in v1.5.0)~~
- **Status:** **RESOLVED.**
- **Resolution:** India's GDP target switched from interpolated annual World Bank data to the OECD QNA quarterly series (`NAEXKP01INQ657S`). With a genuine quarterly series, a SARIMA(1,0,1) component was trained; India is now a full inverse-RMSE ensemble (LGBM 50% + SARIMA 50%) with 95% confidence intervals, and ensemble RMSE improved from 11.51 to 7.60.

### Manual MOCK_DATA Synchronization ~~(RESOLVED in v1.4.0)~~
- **Status:** **RESOLVED.**
- **Resolution:** Implemented hybrid fetching in `dashboard.js`. The frontend attempts dynamic fetching from the cloud API (`/api/dashboard/{country}`) with a 4-second cold-start timeout, falling back gracefully to static `data/forecasts.json` generated by `export_forecasts.py`. The hardcoded `MOCK_DATA` block was removed entirely in v1.5.0.

### Non-Reproducible Feature Pipeline ~~(RESOLVED in v1.5.0)~~
- **Status:** **RESOLVED.**
- **Resolution:** `src/data/build_features.py` now generates all four country feature tables plus the global panel from the processed master CSVs; the monthly workflow retrains every model end-to-end.

## 🔵 Roadmap & Future Enhancements

### 1. Docker Containerization
- **Goal:** Create a `Dockerfile` and `docker-compose.yml` to package the FastAPI backend and Nginx static frontend into a single deployable artifact.

### 2. Multi-Threading Data Ingestion
- **Goal:** Currently, the `fetch_all.py` script downloads FRED data sequentially. Upgrading to `asyncio` and `aiohttp` would reduce pipeline build time by ~70%.

### 3. Exogenous Shock Scenarios
- **Goal:** Add a "Scenario Testing" feature to the UI where users can input custom Interest Rate hikes or CPI spikes and watch how the ensemble models adjust the GDP forecast in real-time.

### 4. Per-Country SARIMA Order Selection
- **Goal:** All SARIMA models currently share (1,0,1)(0,0,0,4). A small grid or AIC-based selection per country (especially India, with its volatile COVID-era swings) could sharpen the SARIMA component.
